# 사건 기반 재결정 (Belief Target Allocation)

작성일: 2026-10-23. 모든 수치는 평가 seed 10000, 30 episode, resolver 없음, 결정적 정책 기준이다. 표의 return은 각 run의 마지막 3회 평가 평균이다. 이론 상한은 12이다(type-1 두 개 10 + type-2 한 개 2, agent 5대 기준).

## 1. 문제: 매초 재결정하면 학습이 되지 않는다

기본값 `decision_interval=1`에서는 agent가 매초 후보를 다시 고른다. 원본 학습(seed 7/8/9, 3M transitions)을 진단한 결과는 다음과 같다.

- 학습 중 확률적 정책은 거의 균일 분포였다. entropy가 최대 2.773 중 2.74~2.77이었다.
- 그래서 매 결정의 92%에서 목표가 바뀌었다. 어떤 작업도 끝나지 않아 학습 중 return은 0이었다.
- 보상이 없으므로 critic Q는 상수가 되었고(표준편차 0), advantage는 1e-8 수준의 잡음이 되었다.
- 결정적 평가는 남아 있는 작은 logit 차이를 따르므로, 평가 시점마다 0~8 사이로 크게 흔들렸다.

균일 임의 정책(12 episode)으로 측정한 return은 재결정 주기에 따라 이렇게 달라진다.

| 재결정 주기 | 1 s | 10 s | 30 s | 100 s |
| --- | --- | --- | --- | --- |
| return | 0.00 | 0.54 | 0.96 | 5.88 |

## 2. 고정 주기 실험

원본 코드에서 설정만 바꿨다. seed는 7/8/9이고 3M transitions까지 학습했다.

| `decision_interval` | return (seed 평균 ± 표준편차) | 성공률 |
| --- | --- | --- |
| 1 (원본) | 2.07 ± 1.37 | 0.05 |
| 30 | 2.71 ± 0.35 | 0.08 |
| 100 | 8.49 ± 0.55 | 0.58 |

- 고정 주기 100에 seed 10/11/12를 추가하면 seed 6개 평균은 5.88이다. 이 중 seed 11은 2.25M에서 디스크 부족으로 중단되었다.
- 고정 주기는 새 객체가 발견되어도 최대 100초 동안 반응하지 못한다.

## 3. 사건 기반 규칙

설정은 `belief_decision_rule="event"`이고 상한은 `decision_interval=1800`이다.

- **재결정 시점:** agent는 자기 작업이 끝날 때 다시 결정한다. 작업 종료 사건은 도착, lawnmower 한 구간 완료, 선택한 대상의 무효화, strike 완료이다.
- **새 정보 인터럽트:** 새 객체가 발견되면 strike 중이 아닌 모든 agent가 다시 결정한다.
- **사건의 출처:** agent별 작업 상태(`task_automaton.py`)가 이 사건들을 만든다.
- **기본값 보존:** 기본 규칙(`interval`)의 rollout은 이전 구현과 비트 단위로 같다(`tests/data/belief_trace_digests.json`).
- **사건 기반 rollout 검증:** 사건 기반 규칙의 rollout도 처음 구현과 같다(`tests/data/belief_event_trace_digests.json`). 처음 구현은 인터럽트를 별도의 belief 사건 검출기에서 받았다.

### 3.1 기본 learning rate에서의 실패와 원인

learning rate 5e-4에서는 return이 seed 7/8/9에서 8.5 / 3.5 / 4.6이었다(평균 5.5). checkpoint별로 정책을 추적하면 다음과 같다.

- 실패한 seed 9는 0.1M transitions(약 10 episode) 만에 정책이 결정적으로 굳었다. 이때 logit 차이는 294였고, 발견한 객체를 선택할 확률은 0이었다. 이후 0.3M까지 학습 중 return이 0이었다.
- 0.6M부터 entropy 항 때문에 정책이 풀렸지만, 거의 균일한 정책에 머물렀다.
- 성공한 seed 7은 0.3M에 "발견한 객체를 고른다"(확률 1.0)는 쪽으로 굳었다.

결론: 학습 극초기에 정책이 너무 빨리 굳어서, 처음 강화된 선호가 seed마다 달라졌다.

### 3.2 learning rate 1.5e-4

| 조건 (rollout 64, 배경 갱신 `local`) | return (seed 7 / 8 / 9) | 성공률 | 학습량 |
| --- | --- | --- | --- |
| 사건 기반, lr 5e-4 | 8.5 / 3.5 / 4.6 → 5.5 | – | 3M |
| **사건 기반, lr 1.5e-4** | **8.75 / 9.12 / 8.83 → 8.90** | **0.70** | 2.5–2.75M (학습 중) |
| 고정 100, lr 5e-4 | 8.4 / 7.9 / 9.2 → 8.49 | 0.58 | 3M |

lr 1.5e-4에서는 seed 3개 모두 1.5M 이후 8.3~9.2를 유지했고, 2M 이후 붕괴하지 않았다.

### 3.3 같은 12 episode에서의 직접 비교

평가 seed는 20000~20011이다. 사건 기반은 lr 1.5e-4 seed 8의 1.53M checkpoint, 고정 주기 100은 seed 9의 3M 최종 모델을 썼다.

| | 사건 기반 | 고정 100 |
| --- | --- | --- |
| 평균 return | 8.08 | 8.75 |
| 성공률 | 0.92 | 0.83 |
| 새 객체 발견 → 처음 선택까지 (중앙값) | 0 s | 19 s |
| 같은 값의 90번째 백분위 | 127 s | 69 s |

사건 기반에서 반응이 긴 경우는 정책이 발견한 객체를 일부러 나중에 처리한 경우이다.

## 4. 학습 안정화 옵션

세 옵션은 기본값이 모두 꺼져 있고, 최종 설정에서는 쓰지 않았다.

| 옵션 | 동작 |
| --- | --- |
| `belief_logit_cap` | 각 agent의 허용 후보 중 최댓값을 기준으로 logit 차이를 `cap·tanh`로 제한한다 |
| `belief_target_kl` | actor minibatch마다 rollout 정책 대비 KL을 계산하고, 기준을 넘으면 그 update를 중단한다 |
| `belief_separate_critic_encoder` | critic에 별도의 belief encoder를 둔다 |

고정 주기 100에서의 결과(seed 3개, 일부 run은 디스크 부족으로 2.0~2.5M에서 중단):
- 세 옵션을 모두 켜면(cap 6) seed 2개는 0.5M부터 8.1~9.0을 안정적으로 유지했다. 나머지 seed 1개는 약 0.7에 머물렀다.
- logit cap만 켜면 return이 0.4~0.9에 머물렀다.

## 5. 한계

- seed가 3~6개뿐이므로 차이의 통계적 유의성은 주장하지 않는다.
- 사건 기반 lr 1.5e-4는 이 문서 작성 시점에 아직 3M까지 학습 중이다.
- 아직 해결하지 못한 문제가 있다. 보고되지 않은 두 번째 편대(F2)의 발견율이 낮고(고정 주기 100 기준 15%), 남은 agent가 이미 탐색한 가까운 구역을 반복해서 다시 탐색한다.
